# 项目协议：userese-video/1

一个项目对应一条目标视频，可含多条原片、多次录制和多个成片版本。核心区分原片证据、剪辑候选、人工决定、构建结果。

## 目录

```text
project/
  project.json        标题、原片索引及哈希、输出宽高
  media/              导入时复制的原片
  evidence/           导入转写文件的原始副本，含可选 ASR 调整记录
  transcript.json     原始时间戳转写，跨原片唯一编号
  script.md           可选原稿快照
  catalog.json        初始语义段与候选
  decisions.json      人工选择、字幕纠错、新候选建议、修改版本
  history/            保存前的历史决定
  cache/              可重新生成的试听片段
  builds/<id>/        当次快照、编码片段、时间映射与交付
  latest.json         最近一次成功构建的清单
```

项目可在不同机器间搬迁。程序只读取项目内的相对素材路径，拒绝父目录穿越和指向项目外文件的符号链接。创建阶段允许从用户给定的外部路径复制素材。

## 创建候选目录

`import --catalog` 接受 JSON 数组。按 `--source` 顺序，原片编号为 `source-001`、`source-002` 等。候选范围引用原片时间，以秒为单位。

```json
[
  {
    "id": "opening",
    "title": "完整开场",
    "suggested": "opening-b",
    "takes": [
      {"id": "opening-a", "label": "第一遍", "parts": [{"source": "source-001", "start": 0, "end": 2}]},
      {"id": "opening-b", "label": "第二遍", "parts": [{"source": "source-001", "start": 2, "end": 4}]}
    ]
  }
]
```

这些时间只是结构示例，真实目录必须对应录音。所有 ID 为 1–80 位字母、数字、下划线或短横线，首字符为字母或数字。语义段 ID 唯一，候选 ID 在整个项目中唯一。

数组顺序就是成片段落顺序。每个候选可包含多个 `parts`，按数组顺序拼接；UI 会将其标为拼接候选。一次录制的不同边界也可以是两个候选，但标签应说明它们是同一遍的长短变体。

区间允许包含停顿，不能切断与其重叠的转写句段。若原始 ASR 分段太长，先根据实际听感与时间戳细化转写，再建立项目；不能把一条完整字幕放到只剩半句话的音频上。

`suggested` 可为候选 ID 或 `null`。导入后状态为 `pending`；带建议不等于已确认。

## 决定状态

| status | 含义 | 是否进入生成 |
| --- | --- | --- |
| pending | 未确认，选择仍为建议 | 仅显式建议版允许 |
| keep | 人工确认使用指定候选 | 是 |
| skip | 人工确认暂不放，take 为 null | 否 |
| optimize | 需要进一步处理 | 阻止生成，含建议版 |

`note` 是意见，保存不代表处理完成。`captions` 将原始 cue ID 映射到人工纠正文字，原始转写不改写；纠错最多 200 字符且为单行纯文本。

`proposals` 将语义段 ID 映射到新增候选数组，结构与 `takes` 相同。`propose` 只增加候选，保留所有人工选择、备注、字幕纠错和审片状态。已有候选 ID 的定义不能改写；快照恢复会保留后来已经交付的候选编号。

导出文件带 `project_id`、`evidence` 与 `revision`。`evidence` 是项目清单、初始目录和原始转写的指纹。导入其他项目或改过证据的快照会被拒绝。每次保存需要提供当前版本；版本冲突必须先导出本页修改，再读取最新版本合并，不能强行覆盖。

## 构建与时钟

一次构建读取一个完整决定快照，核对原片哈希后编码所选区间。输入正向旋转由 FFmpeg 处理，输出按设定尺寸等比补边，25 fps、H.264、yuv420p、AAC 48 kHz 双声道；无声素材补静音轨。音量采用防削波限幅，未声称达到特定平台的响度标准。

每段编码后通过 ffprobe 读取实际视频时长，再累计输出时间。字幕和段落映射使用这个实测时钟，避免长视频因为帧与音频取整逐步漂移。

拼接时显式指定每段实测时长，最终视频帧按 25 fps 重新建立时间戳，避免不同 FFmpeg 版本使用音频填充时长累计出不同的输出时钟。

可选 ASR 适配器将超出实际视频或重叠的模型时间估计限定到有效范围，并同时保存 `raw_segments` 与 `timing_adjustments`。导入项目时保留完整输入文件副本，不把时间修正伪装成模型原始结果。

`builds/<id>/` 包含 `decisions.json` 与 `evidence.json`，因此后续修改不改变历史构建的解释。`manifest.json` 记录源区间、输出区间、字幕时间、视频哈希和检查结果。只有成功完成编码与校验，才更新 `latest.json`。失败构建保留诊断状态，旧成片继续可用。

首帧截图为封面；字幕默认烧录，同时导出 SRT。FFmpeg 去掉源文件元数据及章节，公开投稿前仍需人工查看画面是否含隐私。

## 接口与扩展

CLI 是 AI 与自动化的稳定入口。网页 API 面向当前版本的内置界面，不作为跨版本服务协议。

- ASR：输出标准 JSON/SRT，核心不依赖特定模型。
- 剪辑建议：通过 `--catalog` 初始化，通过 `propose` 追加，不改人工决定。
- 视觉表达：围绕已锁定的输出时间映射扩展；新模板不应偷偷修改口播顺序。
- 交付：读取成功构建的清单；平台上传应由独立流程获得明确授权。

首版只提供字幕布局。自定义导图、抠像和封面模板没有被伪装成已实现功能。
